# RESILIENCE — как сеть «не отключается»

Документ-гарантия. Каждый слой отвечает на вопрос: **«что сломаем — и что произойдёт?»**

---

## 1. Аксиомы неостановимости

1. **Нет центрального сервера** — нет того, что можно DDoS-нуть, выкупить или закрыть.
2. **Нет обязательной входной точки** — bootstrap-источников ≥5 на разных носителях; любой может умереть.
3. **Модель = данные, а не сервис.** Веса распространяются как(content-addressed) файлы по BitTorrent/DHT; даже выключив сеть, любой носит копию и может перезапустить swarm с нуля (seed-list вшит в клиент).
4. **Роли — эфемерны.** Агрегатор/нотариус — временные напоминает-кворумы; падение роли замедляет, но не останавливает: пустое место занимает другой.
5. **Реестр — реплицируем у каждого узла.** «Потерять сеть» = убедить ВСЕ узлы одновременно стереть локальный лог — невозможно; внешний якорь в публ. цепях защищает от переписывания истории.

---

## 2. Bootstrap: пять независимых источников

| # | Источник | Вид отказа | Последствие | Почему живуч |
|---|---|---|---|---|
| 1 | PEX: адреса знакомых пиров с прошлой сессии | нет пиров (мало людей в городе) | отсутствие в swarm до нахождения | работает даже при цензуре; адреса неуникальны |
| 2 | mDNS в локальной сети | нет LAN-пиров | нет локального ускорения | бесполезно блокировать вне дома |
| 3 | DHT (Kademlia, пассивный режим) | фильтрация DHT оператором | замедление | DHT распределена самиших BitTorrent/ext-сообществом; общий файл-слой |
| 4 | DNS-семена (community) | seizure доменов | замедление | домены — \" sacrificeable\"; список обновляется из сети; вшит компактный резерв |
| 5 | Список пиров, встроенный в релиз + распространяемый **как один из чанков модели** (index.json) | подделка списка | защита: подписи хэш-списка и excl. новых | обновляется ТОЛЬКО через саму сеть с кворумом |

Ключевое: **клиент неدает пустую конфигурацию по умолчанию**. Ещё одна {source} — обновление
дистрибутива не завершённых через централизованный фирмварь, а через подписанный magnet.

## 3. Транспортная устойчивость

- QUIC (основной), WebSocket/TLS-443 (fallback) — QUIC фильтруется GFW-style, WS-443 выглядит как веб;
- UDP блок-check: если UDP медленно, переход к SendMessage-over-HTTPS-стиля сообщений через релеи
  участников (ротация; релеи не видят payload — E2E-шифрование);
- Tor/pluggable transport — опциональная сборка (без принуждения, чтобы не 'нарушаться' в регионах, где Tor запрещён).

## 4. Распространение модели

- Magnet-style: model-подбор = DAG чанков SHA-256, реплицирутся как torrent; webseed'ы — опция сообщества;
- **Запуск с нуля**: даже если в стране не осталось ни одного узла, клиент с magnet/reference
  (опубликованный в публичных цепях и как обычная ссылка/QR) собирает сеть заново: 5 Bootstrap-источников + DHT.
- Нотариальная защита подлинности: чек-пойнты с watermark (CamoMark-класс, [v2]) → невозможно
  подсунуть "пойзон" копию через подставного пира.

## 5. Угрозы и контрмеры (матрица)

| Угроза | Поведение | Контрмеры |
|---|---|---|
| Backdoor в весах | malicious-узлы шлют одинак"T-ка" апдейты | norm-band + Krum-консенсус + trimmed mean (v0, проверено сим-тестами 2026-10-25); lazy-аудит 10%; ABS: приток честных гасит |
| Сибилла-экспансия | много ложных узлов | POw-of-training (по времени доказательство эфемерности);_ipv6/local-saturation ругаются; закрепление репутации за ключом, а не IP; денежные входы НЕТ |
| Активный/routes-обход лога | переписывание истории | DAG-append-only + внешние якоря + кворумный подпись чек-пойнтов (CamoMark) |
| Poison-модель via peer | подставные хосты отдают \"битую\" модель | hash-verify чанков; watermark-«отличие» ловится локально |
| некорректный evaluator | преуменьшение метрик | k≥5 evaluators, детерминированный eval-набор (content-addressed), кросс-проверка дисперсии |
| Аматор-агрегатор | видно индивидуальные апдейты | Secure Agg: математически невозможность (pairwise masking) |
| DDoS площадки релеев | выгрузка релеев | релеи ротируются; возможен полный P2P-режим без релеев (медленный: hole-punching, DHT-поиск) |
| Правовой barex «отключите DI-NET» | если закон в стране | типичное: блокировка DNS/горта; наш клиент не требует ни того, ни другого |
| форк/приватизация | кто-то перепродаёт ядро с бэкдором | AGPL-3.0 + отправка build-log; watermark; подписировать чек-пойнты только с доверенных релизов |
| Отказ модели \"сошла с ума\" | деградация качества | fork-choice по eval; постоянно сравнение выживщей ветки; откат к last-good checkpoint |

## 6. SLE: что сеть ГАРАНТИРОВАННО переживает

- съемку любого узла (включая одновременно: все агенты, все нотариусы, все релейки);
- блокировку UDP, DNS-семен, webseed'ов;
- отчуждение 30-50% узлов (модель продолжает сходиться — слайд-окно + порог min_contributors);
- физическое уничтожение всей \"инфраструктуры\": её нет.
