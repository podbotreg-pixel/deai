# DI-NET — архитектура
> Бесплатная для всех, децентрализованная, неостановимая федеративная нейросеть
> (чат + агент + дообучение на клиентских машинах).
>
> Версия: 0.1 · Статус: проект · Референс-промт: `PROMPT.md`

---

## 1. Миссия и неизменяемые принципы

| Принцип | Следствие в архитектуре |
|---|---|
| **Бесплатно для всех** | Нет аккаунтов, оплаты, KYC, телеметрии. Всё ПО — open source (AGPL-3.0 ядро, Apache-2.0 SDK). Любой может стать узлом, включая телефон. Нет «премиум-модели»: одна модель для всех. |
| **Нет владельца** | Ни одного обязательного центрального сервера. Сеть состоит только из клиентских машин. Роли (агрегатор/нотариус) — ротируемые и эфемерные, переходят по репутации. |
| **Нельзя отключить** | Заблокировать можно конкретный домен/сервер — у нас их нет. Модель живёт как content-addressed данные (as torrent/IPFS), сеть — как swarm без входной точки, реестр — реплицированный gossip-лог. См. `docs/RESILIENCE.md`. |
| **Данные принадлежат пользователю** | Диалоги, память, персональный адаптер не покидают устройство. В сеть уходят только DP-обезличенные обновления весов. |
| **Бережно к ресурсам** | Обучение и передача — только когда машина «не нужна пользователю». Жёсткие лимиты RAM/CPU/батареи/трафика (§8). |

**«Что будет, если X исчезнет?» — тест каждого компонента.** Любой компонент, для которого
ответ «сеть не соберётся», запрещён. Расширенная таблица живучести: `docs/RESILIENCE.md`.

## 3. Топология сети (без входной точки)

- **Транспорт:** libp2p (QUIC preferred, WebSocket fallback — QUIC часто блокируется, WS живёт на 443/TLS и выглядит как веб-трафик). Транспорт — pluggable: позже Tor/pluggable-transports как опция. В v0 средства связи разведены в трейт `Transport` (`dinet-node/src/transport.rs`): узлы обмениваются настоящими подписанными wire-кадрами `dinet-proto`; in-memory mesh (тесты) и файловый спул (межпроцессное демо) — первые два backend'а, libp2p подключается как третий без изменения логики эпох.
- **Bootstrap — принцип «многоисточности»** (см. RESILIENCE §2):
  1. `PEX` — адреса пиров, накопленные с прошлой сессии (главный источник, работает offline-восстановление);
  2. mDNS — авто-находка узлов в локальной сети;
  3. DHT — Kademlia, в т.ч. **пассивный режим**: новый узел слушает DHT-подписки и врастает в swarm без единого «сервера контактов»;
  4. DNS-семена — community-volunteer домены (их блокировка бессмысленна: список вшит и обновляем через саму сеть);
  5. Webseed-зерновка модели — магнит-ссылка с webseed-инфраструктурой сообщества; отсутствие webseed'а не блокирует (тор-роутер DHT+PEX сам даёт пиров).
- **Роли (все равноправны, динамические):**
  - `trainer` — любой узел;
  - `aggregator` — ротация каждые N раундов; выбор случайный из зоны доверия (REP ≥ порога);
  - `notary` — кворум ≥5, ротируется; подписывает чек-пойнты;
  - `evaluator` — прогон чек-пойнта на общем eval-наборе (набор — тоже content-addressed, дифференцированный по сети).

**Почему не сервер:** сервер — точка отключения (пример всех ныне «тёрнутых» проектов). Aggregator тратит trình только в окне раунда, после отдаёт роль.

## 4. Модель и локальное обучение

### 4.1 Базовая модель
- Открытая MoE ~5–8B («активных» ≤2B) в GGUF, Q4_K_M по умолчанию (~3–4 ГБ).
  Кандидаты при выборе основной системы: Qwen3-A2B-класс, семейство с permissive-
  лицензией; в документе фиксируется таблица выбора по лицензии/качеству/уровню периферии.
- One rule: **база не хранится ни у кого «с Piца»**; она распространяется как torrent
  (content-address SHA-256 чанков). Один ресурс — миллионы peer'ов-хранилищ.

### 4.2 Контур «speak → learn»
1. Диалог попадает в локальный буфер (в память процесса, диск — только зашифрованным).
2. Триггер обучного мини-цикла (партия ≥20 пар ИЛИ ≥1k токенов ИЛИ явный фидбек).
3. Локальное дообучение **только LoRA-параметров** (r=8..16, base frozen):
   - позитивная часть: маскированная ЛМ-loss на одобренных ответах;
   - преп-ф: DPO/SimPO на (chosen, rejected) с ручного фидбека;
   - приглушённая защита от забывания: LoRA-прокси-регуляризация (KL к текущему
     сетевому адаптеру) — иначе сеть «дышит» от перталкивания.
4. Применяется DP-SGD (per-sample clipping + шум гаусса) с **α-split**-расделением
   бюджетов на компоненты адаптера; ε=6 default (configurable 2–8).
5. Сжатие: блок-квантование 4-bit + error feedback + «векторный банк» (FedFit).
   Natural cap: апдейт ≤ 20 МБ (адаптер+мета, со сжатием ~ 4 МБ).
6. Подпись узлом DID (ed25519), кладётся в gossip-очередь апдейтов.

### 4.3 Относительность знания
| Слой | Хранение | Федерация |
|---|---|---|
| личный адаптер | только у пользователя + зашифрованный бэкап | никогда |
| доменный адаптер (записи/почта/кодирование) | у бассейна узлов, интересующихся темой | да, раз в раунд |
| базовые веса | swarm-cepеDB, чек-пойнты | да, редко, с eval-гейтом |
| навыки (агент) | репозиторий на узле | да, абстрагированные (FAO-принцип) |

## 5. Агрегация (раунд DiLoCo-стиля, асинхронный)

Дизайн: **window-слайд** — не синхронный «мир-раунд», а evergreen поток.

```
trainer  ── UPD_SHARE (зашифрованная частичная сумма + POw-доказательство locale обучения)
   ↓ gossipsub-тема /dinet/rnd/<era_id>/upd
aggregator(N активных) ── Secure Aggregation (pairwise masking, Bonawitz-2017)
   ↓ только сумма N узлов (индивидуальные апдейты математически ненаблюдаемы)
robust step (v0: dinet-node::swarm::robust_screen, проверен сим-тестами):
   1) median norm-band: норма апдейта сравнивается с медианой раунда
      (полоса 0.25x..3x); poison-heavy кадры отсекаются до раскрытия сумм
   2) Krum-консенсус: центр скопления честных; дельты дальше 2.5x медианы
      расстояния отбраковываются (стандартное требование f < n/2)
   3) компонентный trimmed mean (beta=1 с краёв) по принятому множеству
   4) lazy-верификация: случайные ~10% раундов — полный аудит
      (экспресс-eval на общем наборе + Diff-тест знаний до/после)
   Прим.: FedGraph-score (корреляции) остаётся в dinet-fl как v1-инструмент —
   при общем LoRA-init честные дельты коррелируют по дизайну, поэтому
   primary-дискриминатор сговора в v0 — Krum-расстояния.
   ↓
notary-кворум ── CHECKPOINT_ANNOUNCE (hash, parent_hash, eval-метрики, watermark)
   ↓ реплицируется в реестр (append-only gossip-лог)
все узлы: скачивают дельты через torrent/прямую передачу, local-verify (hash+watermark), apply.
```

Управление эпохой: `era_id = f(hash(previous_checkpoint, time_bucket))`.
Aptain: неотсутствующие/офлайн узлы не блокируют раунд — window собирает что есть;
порог min_contributors (например, 50) — ниже: кворум раунда не наступает, апдейты копятся.

**Плазностые атаки → защита**: раздел `docs/RESILIENCE.md §5` (угрозы: backdoor, сибиллы,
активный поток, man-in-агрегатор, ложный eval, replay, DDoS релеев).

## 6. Агентский слой

Ядро — **PAPAV**-цикл (Perceive → Anticipate → Plan → Act → Verify):

- **Perceive:** скрин + AX-дерево (Win UIA / macOS AX / Linux AT-SPI / Android
  AccessibilityService), DOM-снимок браузера (CDP, локальный профиль), CLI-launch.
- **Plan:** план ≤10 шагов, каждый — в журнале с undo-свойствами.
- **Act:** через **MCP-серверы**; каждое действие требует capability-token с TTL.
  Уровни: READ / WRITE(confirm-by-default) / DESTRUCTIVE / NETWORK(confirm+лог).
- **Verify:** VeriCUA-стиль — верификатор знает, что проверять и когда стоп;
  директное повторное наблюдение сотояния (не гл calor сжатие).
- **Recovery:** **ReTrace**-принцип — после ошибки агент возвращается к
  последнему стабильному состоянию (undo-журнал env-действий обязателен).
- **Навыки (Evolving Skills):** после K успешных траекторий формируется навык
  «как сделать X в приложении Y» (без приватных данных — только интерфейс+правила);
  навык подписан, задатирован, распространяется как **SKILL_SHARE**.
  Навыки — первый класс федерации (FAO): делимся умениями, а не траекториями.

### Безопасность агента (жёстко)
- capability-токены, TTL и репутация доменов/приложений;
- анти-фишинг: входящие тексты/ссылки проходят persuasion-детектор (AgentPhishing-тренированный);
 запрет вывода секретов в контекст сети (фільтр секретов на входе MCP);
- глобальная кнопка «СТОП» (системный хоткей) — прерывание с откатом;
- полный журнал действий: экспорт/удаление пользователем всегда.

## 7. Реестр чек-пойнтов (чейн-подобный, без блокчейн-майнера)

Первецифицированный append-only лог, реплицируемый через gossip:
```
Checkpoint = {
  id: SHA256(merge_recipe || parent_id || update_digests),
  parent_id, era_id,
  eval: {ppl, pass@k, entropy, тесты CUA},   // подписано evaluator-кворумом
  watermark: CamoMark-аттестация              // проверка подлинности весов
}
```
- Граф — DAG: допускаются параллельные ветки чек-пойнтов; сеть «голосует» eval-отчётами и
  со временем редуцирует к ветке с лучшей метрикой (fork-choice = max weighted eval).
- Периодический якорь: раз в ~7 дней хэш головы записывается в несколько публичных
  блокчейно *и* в ipfs/DHT-заявки — независимая внешняя точка отсчёта (защита от
  переписывания истории и от подавления реестра). Анкоры бесплатны и децентрализованны.

## 8. Бюджет ресурсов (жёсткие лимиты)

| Режим | CPU/GPU | RAM | Сеть | Энергия |
|---|---|---|---|---|
| Чат | ≤6 потоков, low-pri | база mmap + KV ≤1.5 ГБ (desktop) | 0 (локально) | обычный |
| Агент | как чат + waiter-оверлей | +250 МБ | доменные (MCP) | обычный |
| Обучение (фон) | ≤50% одного приоритет-класса | ≤2 ГБ (desktop) / ≤1.2 ГБ (mobile) | ≤20 МБ/img Wi-Fi-only | Останов ≤2 с |
| Idle (swarm) | 0 активного | 60–120 МБ | DHT ≤5 кБ/мин; gossip по событиям | ~0 |

Триггеры старта обучения: **(зарядка ИЛИ батарея>70%) И (утилизация CPU<20% 15 мин) И (не
«рабочие часы», если задал) И термально OK**. Мобильные: WorkManager + «Wi-Fi + un-metered +
charging only».

`crates/dinet-core/src/scheduler.rs` — единственный Autority по расписанию; UI
обязана ю-ать всегда показ: что делает узел, сколько съел, кнопки пауза/стоп/ограничить.

## 9. Стек

- **Ядро:** Rust (стабильный), workspace: `dinet-core` (планировщик, конфиг),
  `dinet-net` (transport/DHT/gossip), `dinet-fl` (DP-SGD, secure agg, сжатие),
  `dinet-proto` (wire-сообщения), `dinet-crypto` (ed25519/DID/HASH).
- **Инференс:** llama.cpp binding (GGUF), MLX на macOS. [{ОТКРЫТО}: NPU-путь]
- **UI:** Tauri 2 (desktop), Compose (Android). Кубо: общая REST/IPC-обвязка узла.
- **Крипто:** ed25519-dalek, X25519 + Noise, SHA-256 content addressing, Merkle.
- **Хранилище:** SQLite (+sqlite-vec для RAG), локальные логи append-only.
- **Лицензии:** ядро AGPL-3.0 (анти-privатизация), SDK/протокол Apache-2.0.
