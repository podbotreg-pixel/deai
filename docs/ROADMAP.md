# ROADMAP — DI-NET

> Принцип: каждая фаза имеет работающий артефакт, а не «план на бумаге».
> Free / decentralized / unstoppable — проверяется в каждой фазе.

      `blob_torrent::torrent_blobs` — протокол
      `BlobNeed/BlobHave/BlobChunkReq/BlobChunk`
      (dinet-proto 0x50–0x53, канал CH_BLOB): держатель отвечает каноном
      манифеста (sha256-связка с id), просящий собирает недостающее
      round-robin по НЕСКОЛЬКИМ сидам, куски верифицируются хэшами;
      «полный сид» = все куски непусты (частичный обязан самолечиться).
      Тест: 6 узлов (1 byz) × 2 masked + REVEAL: у узла 0 вайп склада,
      у узла 2 — потерян кусок; оба собирают блоб из чужих кусков
      БИТ-В-БИТ с эталоном, кусок узла 0 берётся у чужого источника.
- [x] Синхронизация реестра для пришедшего узла (догон append-only лога):
      ФАЗА H `reg_sync::reg_sync` — протокол `RegAsk/RegOffer`
      (dinet-proto 0x54–0x55, канал CH_REG): отставший/новичок
      broadcast'ит, сколько записей имеет; держатели длинных хвостов
      отвечают направленно СЕТЕВЫМИ байтами записей
      (`dinet-registry::encode_record` — тот же формат, что хвост файла:
      persist и сеть не расходятся ни байтом); записи ДОПИСЫВАЮТСЯ через
      обычный `RegistryLog::append` — цепочка seq/parent, подписи печатей
      и кворум перепроверяются заново на чужих байтах. Офферы
      round-нейтральны (несвоенный оффер принимается наравне). Тесты:
      1) «новичок присоединился»: 4 узла прошли 3 эры, приходит узел 4 с
      пустым логом → фаза H догоняет реестр бит-в-бит с эталоном,
      следом фаза G доливает блоб из кусков; 2) подделка (чужой
      seq/подпись нотариуса поверх своего канона) отклоняется append'ом,
      при этом честный хвост прицепляется и файл остаётся бит-в-бит
      идентичен эталону.
- [x] Внешние якоря (анти-откат): ФАЗА I `anchors` — кольцо
      независимых сервисов (без ключей роя и без весов) держит ТОЛЬКО
      пары (seq, checkpoint_id) голов реестра:
      `AnchorStamp/AnchorAsk/AnchorTell` (dinet-proto 0x56–0x58, канал
      CH_ANCHOR). Кворум эры штампует голову после нотарного append;
      анкор коммитит пару только при `notary_min(roster)` РАЗНЫХ
      подписей роя и не откатывает свои комиты (файл растёт 36 байтами
      за эру, дружит с переоткрытием); два разных кворума на одном
      seq взаимно гасятся. Узел рестарта спрашивает кольцо и вердиктит
      (`restart_verdict`): пара большинства (anchor_min анкоров) есть
      в родной parent-цепочке — Ok, нет — Fork (укороченный хвост,
      подменённый файл) → реестр догоняется ФАЗОЙ H у пиров. Тесты:
      1) кворум коммитит честные головы, левая (валидным ключом роя)
      голова кворума не набирает и не коммитится, файл анкора
      бит-в-бит переживает переоткрытие; 2) жертва с урезанным
      хвостом даёт Fork, остальные Ok — фаза H добирает хвост, после
      чего жертва снова показывает подкреплённую голову (Ok).
- [x] Hello/PEX с pubkey (связка v1-ключей): ФАЗА J `join::hello_join` —
      новичок со СГЕНЕРИРОВАННЫМ ed25519-ключом объявляет сеть кадром
      `Hello 0x01` (подпись проверяется ключом ИЗ поля sender: верификатор
      строится на лету — TOFU); встречные заносят ключ через
      `PeerBook::enroll` (публичный API книги: enroll/knows/senders/
      verifier/len) и целят `HelloAck 0x02` со списком известных
      ключей (PEX); новичок TOFU-заносит Ack'и в свою книгу. Проверено:
      повторный кадр новичка верифицируется УЖЕ ЗНАЮЩЕЙ книгой
      встречного, а подделка (кадр «от лица новичка», подписанный
      чужим ключом) отвергается, книга не пополняется, подделка
      учтена в rejected_frames (TOFU не впускает). Канал CH_HELLO = 7.

**DoD:** 100 контейнеров (200 Mbps/5% loss эмуляция): метрики сходятся после N эпох;
10% malicious-узлов не могут сдвинуть eval на > заданный δ; выключение любого
агрегатора/нотарriуса/релея замедляет, но не останавливает.

## M2 — Инфосфера (требования участников, 2026-10)

1. **GUI без ручного обучения**: клиент тренируется сам, пока запущен
   (фон/таймер, не привязка к ходам диалога).
2. **Обучение на опыте**: диалоги с пользователем + поиск информации
   в интернете становятся обучающим материалом.
3. **Общая память роя**: узлы регулярно обмениваются содержимым ради
   лучшего результата — и в обучении, и в общении.
4. **Распределение — «инфосфера»**: записи реплицируются по узлам;
   полного хранилища в одном месте нет.
5. **Содержимое**: единицы опыта (диалоги, извлечённые факты),
      общие знания и ИНСТРУКЦИИ по обучению и общению участника роя.)

- [x] Общая память роя: узлы РЕАЛЬНО обмениваются содержимым —
      модуль `dinet-client::infosync` (std-only): тик обмена поверх
      ЛЮБОГО Transport с каналом CH_INFO — collect чужого / пуш своих
      (квота 8 анонсов за тик — вежливо) / ответы телами на аски /

      самоверифицируемы TOFU (sender = pubkey в кадре); за тики
