# МЕГА-ПРОМТ: Децентрализованная федеративная нейросеть «DI-NET»
## (чат + агент + распределённое дообучение на клиентских машинах)

---

Ты — главный архитектор ИИ-системы и технический лид. Спроектируй и опиши реализацию
децентрализованной,Privacy-First нейросети, которая:

1. Работает **локально** на машинах пользователей (Windows, Linux, macOS, Android).
2. Имеет **два режима**: (а) приватный чат с пользователем, (б) **агент**, управляющий
   ОС, установленными программами, браузером и социальными сетями пользователя
   (только по явному разрешению).
3. **Дообучается после общения с каждым клиентом** без отправки его данных в облако:
   локально считается обновление (LoRA-адаптер), а не сырые сообщения, и через
   федеративный/децентрализованный механизм модель **всей сети** улучшается.
4. Не имеет единого сервера-владельца: P2P-топология, репликация весов, устойчивость
   к Византийским (злонамеренным) участникам.
5. **Бережно расходует ресурсы** устройства (CPU/GPU/RAM/батарея/трафик), никогда
   не мешает пользователю работать.

## 1. Научная база (обязательные источники)

Опирайся на современные работы по федеративному и децентрализованному обучению LLM.
Включи в документ раздел «Научное обоснование» со ссылками:

**Классика федеративного обучения (фундамент):**
- FedAvg (McMahan et al., 2017) — усреднение локальных обновлений;
- FedProx (Li et al., 2020) и SCAFFOLD (Karimireddy et al., 2020) — борьба с non-IID/дрейфом;
- DP-FedAvg / DP-SGD (Abadi et al., 2016; McMahan et al., 2018) — дифференциальная приватность;
- Secure Aggregation (Bonawitz et al., 2017) — анонимное суммирование обновлений;
- Krum / Trimmed-Mean (Blanchard et al., 2017) — Византийско-устойчивая агрегация;
- DILoCo (DeepMind, 2023) — федеративное дообучение редкими крупными раундами,
  пригодное для unreliable-сетей (наша основа для расписания синхронизации).

**Свежие работы (2025–2026), прямо релевантные нашей задаче:**
- **FedGraph** (arXiv:2610.18430) — защита от backdoor-атак при федеративном
  LoRA-дообучении LLM через графовую агрегацию обновлений: malicious-клиенты дают
  «слишком согласованные» апдейты; подавлять их при агрегации.
- **HMP-GAE / Byzantine-Resilient FedLLM** (arXiv:2610.12711) — гиперграф message
  passing над LoRA-обновлениями для отсева семантически «отравленных» вкладов.
- **CamoMark** (arXiv:2610.14289) — водяные знаки, устойчивые к агрегаторам
  (для проверки подлинности общих чек-пойнтов).
- **Distributed Subliminal Learning (DSL)** (arXiv:2610.05378, NeurIPS 2026 CODEC-FM) —
  обмен **не параметрами**, а поведением на случайных carrier-входах
  (logits/completions), upload меньше в 30–49 раз; резервный канал слияния знаний.
- **FedFit** (arXiv:2610.01537) — федеративный LoRA через «векторные банки» +
  поквантованное сжатие с client-side error feedback; сжатие до 100×.
- **FLoKD** (arXiv:2609.13580) — дистилляция через промежуточные LoRA-активации
  вместо параметров; −50…65% трафика (альтернатива для слабых устройств).
- **Optimal Hydra** (arXiv:2610.20753) — гетерогенная федеративка: разные клиенты
  обучают разные подсети (Hydra-nets) под свои ресурсы/данные.
- **Federated Agent Optimization (FAO)** (arXiv:2610.01195) — постановка задачи:
  агенты делятся не весами, а абстрагированными capaностями: policy, память,
  навыки, функции награды, знания. Это источник для «агентского контура» обучения.
- **EFFEKT** (arXiv:2608.08138) — лёгкий клиентский прокси-модель обучается локально
  и передаёт знание большой server-side модели через cross-distillation
  (шаблон для слабых устройств: телефон обучает 0.5B-прокси).
- **α-split DP** (arXiv:2609.11762) — раздельные DP-бюджеты на компоненты модели,
  чтобы приватность не убивала полезность.
- **Communication-Efficient LLM Adaptation over Decentralized GPU Meshes**
  (arXiv:2609.14339) — двухконтурная асинхронная схема (fast compressed + slow anchor),
  40×+ сжатие по медленным каналам; шаблон нашего сетевого слоя.
- **Greedy Local Learning** (arXiv:2610.04867) — покомпонентное обучение без полного
  backward-pass (экономия памяти на градиентах; важно для мобильных).
- **The Power of Backdoor Absorption in Community Training** (arXiv:2607.06643) —
  DTMC-модель, показывающая, что постоянный приток честных обновлений +
  выборочная lazy-верификация ~10% шагов подавляет backdoor с вероятностью → 0.

**Агентский стек (computer-use):**
- **Agent S4 / Evolving Agent Interfaces** (arXiv:2610.28601) — интерфейсы действий
  эволюционируют из опыта (репозиторий «навыков»), SOTA на OSWorld V2.
- **CUA-Recovery / ReTrace** (arXiv:2610.27645, 2610.27954) — error-awareness и
  восстановление после ошибок как первичный навык агента.
- **WildAWM** (arXiv:2610.26828) — синтез обучающих сред (GUI + MCP + CLI) для
  обучения computer-use агентов у нетворкинг-клиентов.
- **VeriCUA** (arXiv:2610.26469) — pro-active верификатор действий как источник
  награды для RL агента.
- **CUA-Lite** (arXiv:2610.26071) — открытая платформа/бенчмарки CUА — база для
  нашего набора тестов агента.
- **PAPAV** (arXiv:2610.30108) — каркас способностей: Perceive → Anticipate →
  Plan → Act → Verify. Используй его как скелет агентского цикла.
- **AgentPhishing** (arXiv:2610.31404) — бенчмарк устойчивости агентов к
  социальной инженерии: обязательный тест-набор нашего агента.

Полный список работ явно перечисли в разделе «Библиография» документа, со статусом:
`[реализуем в v1]` / `[реализуем в v2]` / `[исследуем]`.

## 2. Топология сети (децентрализация)

Спроектируй смешанную P2P-топологию без единого владельца:

- **Транспорт**: libp2p (gossipsub, QUIC/TCP, NAT traversal через hole-punching,
  circuit relay как опциональные публичные релеи — релеи не видят содержимое,
  т.к. payload зашифрован).
- **Обнаружение пиров**: DHT (Kademlia) + mDNS в локальной сети.
- **Репликация весов/датасетов общего пула**: BitTorrent-совместимый протокол
  (или IPFS-style content-addressed chunks), чтобы крупная базовая модель не
  качалась с одного сервера.
- **Реестр версий модели**:区块链-подобный append-only лог чек-пойнтов (можно
  как a L2 на существующей цепи или свой gossip-реестр) — каждый чек-пойнт
  подписан-tagрейс-класт aggregates; верификация через CamoMark-подобные watermark
  + коллективную проверку качества на открытом eval-наборе.
- **Роли узлов** (все равны, роли динамические и ротируемые):
  - `trainer` — считает обновление на своём локальном опыте;
  - `aggregator` (ротация каждые N раундов, выбор по stake-of-work/репутации) —
    собирает зашифрованные частичные суммы (Secure Aggregation);
  - `notary` — подписывает и публикует чек-пойнты (кворум из ≥5 нотариусов);
  - `evaluator` — прогоняет новый чек-пойнт на общем eval-наборе и отдаёт метрики.
- **Асинхронность**: никаких синхронных миров-раундов; updates летят асинхронно,
  агрегация — sliding window (идея DiLoCo + Communication-Efficient GPU Meshes).

Обоснуй_topology с диаграммой и числами: пиров 10³–10⁵, апдейт≤10–50 МБ сжатых.

## 3. Модель и локальное обучение

### 3.1 Базовая модель
- Открытая маломодель-магистраль (2–8B параметров, MoE-приоритет: активных
  параметров ≤2B для слабых машин; например семейство Qwen3-Lite/Phi/яь Lama-3.x-класса —
  конкретный выбор обоснуй по лицензии и качеству).
- Формат GGUF + llama.cpp (или MLX на macOS) — единый инференс-движок на всех ОС.
- Персонализация: **локальные LoRA/QLoRA-адаптеры** (r=8…16), никогда не сливаются
  в базу; у пользователя свой личный адаптер + общий «сетевой» адаптер.

### 3.2 Локальное дообучение после каждого диалога
Логика «speak → learn»:
1. Диалог.pkl в локальный буфер (heat-память уровня «сессия»).
2. Когда буфер достигает порога (например ≥20 пар user/assistant и ≥1k токенов) ИЛИ
   пользователь явно правки/лайк/дизлайк — запускается **локальный мини-трейн**:
   - objective: DPO/SimPO на парах (chosen=pushпрáвленный ответ, rejected=неапрувнутый)
     + маскированная LM-loss на одобренных ответах;
   - только LoRA-параметры; base заморожен; 1–5 локальных эпох; батч=1, grad-accum;
   - опционально блок-локальное обучение (Greedy Local Learning) для слабых устройств.
3. Обновление анонимизируется: тексты диалогов **удаляются** после вычисления
   градиента; из апдейта не должно извлекаться содержимое
   (DP-SGD с per-layer α-split клип-бюджетами, ε=2–8 конфигурируемо).
4. Апдейт сжимается (FedFit-стиль: векторный банк + 4-битная блочная квантование
   + error feedback) и подписывается пользователем did-подписью.

Различай три уровня знания:
- **личный адаптер** (никогда не покидает устройство);
- **клубный/доменный адаптер** (например «письма», «социльные сети» —
  федеративно агрегируется);
- **базовый вес** (федеративно обновляется редко, с кворумом и eval-гейтом).

## 4. Агрегация и защита сети

Опиши пайплайн одного «раунда» обучения:

1. Клиент шифрует сигнал по схеме Secure Aggregation (пары попарных масок,
   частичные суммы; выхода индивидуального апдейта нет).
2. Агрегаторы используют составную защиту:
   - trimmed mean / Krum по нормам;
   - FedGraph-фильтр: граф корреляций обновлений, ловим «слишком похожие»
     (коллективный backdoor) и «выбивающиеся»;
   - HMP-GAE-подобная семантическая проверка через общие отклики модели до/после
     слияния на общем eval-сете (ppl / semantic entropy).
3. Lazy-верификация: выбирается случайные ~10% раундов для полной аудита
   (идея Backdoor Absorption) — большинство раундов дешёвые, редкие — дорогие.
4. Слияние: weighted FedMA-like/spectral aggregation (FedFit), либо DSL-канал:
   обмен carrier-logits на общих случайных данных и дистилляция —
   используй как fallback для гетерогенных клиентов (EFFEKT-стиль).
5. Публикация чек-пойнта: кворум нотариусов + подпись + метрики eval + watermark.

Обязательно опиши **угрозы** и контрмеры: отравление данных, backdoor в весах,
сибиллы-узлы, активный aggregator, приватность-через-обязановку индивидуальных
апдейтов, DDoS на релеи, МАНИМуляция метрик eval. Для каждой — конкретный контроль.

## 5. Агентский слой (режим «агент»)

### 5.1 Ядро агента
- Цикл по PAPAV: Perceive (скрин/AX-дерево/a11y-снимок) → Anticipate → Plan
  (ToT-план, шаги ≤10) → Act → Verify (проверка результата действия).
- **MCP (Model Context Protocol)** как универсальный интерфейс инструментов:
  MCP-серверы для:
  - файловая система (настраиваемая песочница);
  - терминал/CLI (allow-list команд);
  - GUI-автоматизация: Windows UI Automation, macOS Accessibility/AppleScript,
    Linux AT-SPI/XDG, Android AccessibilityService;
  - браузер (CDP/Playwright-приватный, только локальный профиль);
  - приложения (API-уровень: Outlook/Telegram/… через их интерфейсы);
  - соцсети: только через официальные API + явный OAuth-контент-пользователя
    (гарантировать: никаких бото-действий, никаких постинг-действий без подтверждения).
- **Evolving Skills**: репозиторий навыков («как выполнить Z в приложении X»),
  который сам пополняется из успешных траекторий (Agent S4-стиль); навыки —
  **первоклассный объект федеративного обмена** (FAO: делимся skills/rewards,
  а не приватными траекториями).
- **Recovery**: обязательная проверка/откат (ReTrace/CUA-Recovery): каждое действие
  окружения пишет undo-журнал; agent умеет вернуться после ошибки.
- **Память**: локальная RAG (SQLite-vec / QDRANT-lite, эмбеддинги локальной малой
  моделью); долговременная память — тоже **личная**, не федерируется; федерируются
  только обобщённые навыки/осведомлённости с DP- quiбы.

### 5.2 Безопасность агента (критический раздел)
- Действия классифицируются: READ (безопасно) / WRite (подтверждение по умолчанию)
  / DESTRUCTIVE / NETWORK-EXTERNAL (подтверждение+лог).
- Replика-actions разрешённого канала; «задача недели» видна в системном трее.
- Мандаты (capability tokens) с TTL на каждое приложение/домен.
- Anti-phishing: прогон входящие смыслов через модели-детекторы persuasion
  (см. AgentPhishing), блокировать экфи-вывод секретов (API-ключи, токены).
- Man-in-the-loop кнопка «стоп/откат» всегда доступная.
- Прозрачный журнал всех действий, экспортируемый пользователем.

## 6. Кросс-платформенное приложение

- **Ядро (общая библиотека) — Rust**: фл-движок (llama.cpp/MLX-binding),
  FL-клиент, крипто, сетевой слой (libp2p-rust), локальные БД. Один источник правды.
- **UI-оболочки**:
  - Windows/Linux/macOS — Tauri 2 (WebView) + системный трей + глобальные хоткеи
    (или для Linux доп. флаг под Wayland/Portal-ограничения);
  - Android — Kotlin/Compose UI + JNI-обвязка Rust-ядра;
  - (опционально) iOS — v2 как отдельная фаза, не блокирует v1.
- **Чат-режим**: локальный UX (папки, экспорт, поиск по памяти, «забудь это» —
  кнопка удаления данных из памяти и отзыва вклада).
- **Агент-режим**: боковая панель (desktop), overlay-кнопка (Android), со списком
  текущих действий в реальном времени и кнопками «стоп/откат».
- **Установка**: подписанные пакеты (MSIX/AppImage/.dmg/APK), авто-обновление
  ядра через тот же P2P-канал с подписью.

## 7. Экономия ресурсов (обязательный раздел — с цифрами)

По умолчанию приложение — **вежливый гость** в системе:

- **Инференс**:
  - квантование Q4_K_M / IQ4 по умолчанию, Q8 — опция;
  - MoE: активация ≤2B при 5–8B «мозга»;
  - офFocused KV-cache: сжатие (quantized KV), авто-тримминг;
- **Расписание обучения** (никогда не мешает пользователю):
  - триггер: устройство на зарядке ИЛИ батарея >70% ИЛИ CPU/GPU-утилизация <20%
    в течение 15 мин ИЛИ «ночь» по местному времени;
  - Windows/Linux/macOS — `low priority`/`nice`/`QoS` + cap 50% одного треда;
  - Android — WorkManager Expedited-нет: только на зарядке + Wi-Fi + термальном OK;
  - остановка в течение ≤2s по signal от ОС (термальный/батерейный-JVM-林);
- **Память**: mmap весов, lazy загрузка экспертов, лимит RSS (напр. ≤2 GB desktop,
  ≤1.2 GB Android); streaming-инференс (prefill/decode разбит на чанки);
- **Сеть**: обновление ≤20 МБ сжат; schedule отправок только на Wi-Fi/безлимит,
  DHT-трафик ≤5 кБ/мин в idle; счётчик трафика в UI;
- **Энергия**: интеграция с Battery API/thermal throttling; расход ≤X Вт в обучении —
  покажи фактическое потребление в UI;
- **Диск**: база ~3–5 ГБ (сжатая), адаптеры кБ-МБ, memory-индексы ≤500 МБ,
  авто-очистка старых чек-пойнтов (держать 2 последних + подписанный stable).

## 8. Стек технологий (итоговые выборы, зафиксируй их в документе)

- Ядро/инференс: Rust + llama.cpp (GGUF); MLX на macOS; NPU-ускорение где есть
  (DirectML/CoreML/NNAPI/QNN — [ОТКРЫТЫЙ ВОПРОС], оцени трудозатраты).
- Обучение: PyTorch-микс (desktop-training mode) ИЛИ чистый Rust training стак
  (Burn/candle) — обоснуй окончательный выбор с trade-offs.
- FL-фреймворк: свой минималистичный клиент (0 зависимости от сервера)
  — протокол описать самим, вдохновляя Flower/OpenFL — но **без их server-side**.
- Сеть: libp2p (rust-libp2p), gossipsub, DHT, QUIC; BitTorrent-стиль репликация весов.
- Крипто: ed25519-подписи (did:key), X25519 + Noise — для каналов, Secure Aggregation
  (pairwise masking, Bonawitz-2017), SHA-256 content-addressing, Merkle-деревья.
- Реестр: append-only gossip-лог (не обязателен полноценный区块链; допустимо
  «gossip + кворум нотариусов + периодические якоря в публичную цепь»).
- Инструменты агента: MCP-спецификация, a11y-APIs, CDP.
- UI: Tauri 2 (desktop), Compose (Android).

## 10. Дорожная карта и критерии приёмки

Фазы:
1. **M0 (4 нед)**: локальный чат с llama.cpp + личный LoRA-DPO-цикл на ручном
   фидбеке. DoD: на среднм laptop (CPU-only, 16 GB) диалог≤15 токенов/сек;
   обучение 20 пар ≤20 мин в фоне, батарея не страдает.
2. **M1 (6 нед)**: P2P-слой + Secure Aggregation + базовая Византийская-защита.
   DoD: 100 тестовых узлов (контейнеры, эмуляция 200 Mbps/5% loss) сходятся;
   10% malicious не могут сдвинуть model damage >δ на держащем eval.
3. **M2 (8 нед)**: агент desktop (FS+CLI+браузер+UIA/AX/AT-SPI) + UI + undo/журнал.
   DoD: ≥20 задач на CUA-подобных открытых бенчмарках, succ≥50%, phishing-тест
   не «сдаёт» секреты.
4. **M3 (8 нед)**: Android-клиент + синхронизация на мобильных + EFFEKT-прокси.
5. **M4 (постоян.)**: DSL-канал, skill-эволюция, дарvin-репутация, watermark, DAG.

Метрики сети для раздела реестра: perplexity на общем наборе, MT-Bench-подобный
offline-eval, % bad-обновлений отсечённых, трафик/раунд/пир, энергия/раунд/пир.
